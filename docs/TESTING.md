# Тестирование

## Локальные проверки перед коммитом

```bash
python3 -m py_compile src/yandex_function/handler.py
node --check src/cloudflare_worker/worker.js
git diff --check
git grep -nE '(TELEGRAM_BOT_TOKEN=.+|BEGIN PRIVATE KEY|service_account.*json|docs.google.com/spreadsheets/d/[A-Za-z0-9_-]+)'
```

Последняя команда не должна вернуть реальных конфигурационных значений. Шаблоны и имена переменных допустимы.

## Приемка чистой копии

| Сценарий | Действие | Ожидаемый результат |
| --- | --- | --- |
| Обычный текст | Отправить боту `Подготовить отчет`. | Одна строка во Входящих, короткое подтверждение. |
| Пересланное сообщение | Переслать текст другому автору. | Одна строка с исходным текстом и автором, без дублей. |
| Доработка черновика | Написать неполную формулировку, дописать в пределах задержки. | Создается только итоговая задача. |
| Задача | Указать формулировку и тип `задача`. | Есть задача и одна базовая подзадача. |
| Ручные входящие | Внести несколько строк без ID и заполнить формулировки. | Скрипт выдает каждой строке уникальный ID; после двух минут без правок создает задачи без взаимного сброса таймера. |
| Рутина | Создать ежедневную active-рутину. | Есть экземпляр на сегодня; завтра создается новый даже если вчера не закрыт. |
| Покупка | Отправить `Купить масло`. | Позиция видна в списке покупок и Плане дня. |
| План | Поставить подзадаче дату сегодня и оценку. | Видна в Плане дня, `/today` и утреннем сообщении. |
| Исходная дата события | Указать историческую дату рождения или кончины и ежегодное повторение. | Исходная дата сохраняется, Дата события рассчитывается на ближайший год. Для 29 февраля в невисокосный год используется 28 февраля. |
| Ширина событий | Изменить ширину колонок Важных событий и запустить автоматизацию. | Ручная ширина сохраняется. |
| Порядок событий | Перенести целиком колонку Исходная дата к началу листа и запустить автоматизацию. | Заголовки, значения и оформление остаются на выбранных местах; расписание читается по именам колонок. |
| Порядок рабочих листов | Перенести целиком любую служебную или ручную колонку в «Входящих», «Задачах», «Подзадачах», «Рутинах», «Покупках», «Справочниках», «Сводках» или «Итогах недели», затем запустить автоматизацию. | Порядок и визуальное оформление сохраняются; новые строки и обновления попадают под нужные заголовки. |
| План после перестановки | Перенести колонки «Раздел», «Закрыть», «Подзадача» или «Статус» в «ПЛАНЕ ДНЯ»; также перенести столбец «Статус» в «Подзадачах» и «Списке покупок». | План строится по текущим заголовкам; ссылки «Закрыть» и «Купить» ведут в реальную ячейку статуса. |
| Ручное оформление | Изменить ширину, фон или шрифт существующей колонки и запустить автоматизацию. | Скрипт не переписывает ручное оформление. Оформление по умолчанию задается только для нового листа или нового отсутствующего поля. |
| Резерв уведомлений | Временно указать недоступный URL Function и вызвать плановую отправку. | План приходит через Cloudflare Worker. |
| Закрытие | Нажать `Done` в `/today` или `/hot`. | Статус подзадачи `done`, бот отвечает `Обновил`. |
| Пагинация | Создать больше пяти открытых подзадач. | Кнопки показывают страницы, текст не обрывается внутри задачи. |
| Статус задачи | Закрыть все ее подзадачи. | Статус задачи становится `done`. |
| Пустые входящие | Оставить ноль новых входящих к 08:00. | Напоминание не приходит. |

## Регресс после изменений

После изменения формул, статусов или расписания повторить все строки приемки. После изменения Worker отдельно проверить Telegram webhook через `getWebhookInfo`; после изменения Function проверить логи Yandex Cloud; после изменения Apps Script проверить страницу Executions.

Важно: разрешено переставлять целые колонки и менять их оформление. Нельзя переименовывать или удалять обязательные заголовки: автоматизация использует их названия, а не буквы столбцов.
