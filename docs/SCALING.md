# Масштабирование

## Текущий MVP

Один бот обслуживает одну таблицу и один chat. Идентификаторы задаются как переменные окружения Function. Такая модель проста в эксплуатации, но не поддерживает нескольких независимых пользователей без изменения конфигурации.

## Целевая модель нескольких пользователей

Нужен отдельный реестр подключений, доступный только администратору:

| Поле | Назначение |
| --- | --- |
| `chat_id` | Ключ Telegram-чата. |
| `spreadsheet_id` | Реестр пользователя. |
| `service_account_profile` | Указатель на секрет доступа. |
| `timezone` | Локальное расписание сообщений. |
| `active` | Разрешение на обработку. |
| `plan_limit_minutes` | Индивидуальный лимит нагрузки. |

Function определяет пользователя по `chat_id`, загружает его конфигурацию, а все запросы ограничивает этой записью. Данные разных таблиц не смешиваются. Секреты остаются в Secret Manager или переменных облака; сам реестр не коммитится.

## Последовательность внедрения

1. Выделить конфигурационный слой вместо глобальных `ALLOWED_CHAT_ID` и `SPREADSHEET_ID`.
2. Создать защищенный реестр подключений.
3. Добавить onboarding новой таблицы и проверку доступа service account.
4. Сделать расписания по часовому поясу пользователя.
5. Добавить изоляционные и нагрузочные тесты для нескольких чатов.
