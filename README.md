# Multytrack

Переносимый Telegram task tracker на базе Google Sheets. Пользователь отправляет или пересылает сообщение боту; оно попадает во `Входящие`, а работа с задачами происходит в Google Таблице. Бот показывает план, просрочки и позволяет закрывать подзадачи кнопкой.

Проект не хранит рабочие задачи, персональные данные, ссылки на конкретные таблицы, идентификаторы облака или секреты. Конкретный реестр остается в Google Sheets владельца.

## Состав

| Компонент | Роль |
| --- | --- |
| `src/yandex_function` | Прием Telegram webhook, запись во Входящие, команды и кнопки. |
| `src/cloudflare_worker` | Публичный HTTPS relay между Telegram, Yandex Cloud и исходящими сообщениями. |
| `src/google_apps_script` | Логика таблицы: сущности, обработка Входящих, рутины, План дня, расписания. |
| `docs` | Архитектура, настройка, сценарии, тестирование и эксплуатация. |

## Быстрый старт

1. Создайте копию Google Таблицы и привяжите к ней Apps Script из `src/google_apps_script`.
2. Создайте сервисный аккаунт Google и дайте его адресу доступ редактора к копии таблицы.
3. Разверните Yandex Cloud Function из `src/yandex_function`, задав переменные окружения из [Configuration](docs/CONFIGURATION.md).
4. Разверните Cloudflare Worker из `src/cloudflare_worker`, добавьте секреты и направьте Telegram webhook на Worker URL.
5. В таблице выполните `Таск-трекер -> Восстановить автоматизацию`.
6. Пройдите приемочные сценарии из [Testing](docs/TESTING.md).

Подробные инструкции: [архитектура](docs/ARCHITECTURE.md), [настройка](docs/CONFIGURATION.md), [сценарии](docs/USER_SCENARIOS.md), [эксплуатация](docs/OPERATIONS.md).

## Границы MVP

Текущая конфигурация рассчитана на один Telegram chat и одну таблицу: это закрепляется переменными `ALLOWED_CHAT_ID` и `SPREADSHEET_ID`. Для нескольких независимых пользователей нужна таблица-реестр подключений `chat_id -> spreadsheet_id -> настройки`; план описан в [Scaling](docs/SCALING.md).
